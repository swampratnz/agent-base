# Code Audit — `swampratnz/agent-base` (v0.6.4)

**Date:** 2026-08-25
**Commit reviewed:** `7f88060` (main)
**Method:** general engineering review of the full tree, plus a dedicated security review by a separate agent covering `docs/SECURITY.md`'s invariants, the storage layer, the auth/RBAC spine, outbound filtering, the CONFIRM flow, `safeFetch`, and all four GitHub workflows. Every finding was verified against the code; where a check could be executed it was (`npm audit`, the full local gate set, a direct harness against `safeFetch`'s IP denylist).

## Executive summary

| Severity | Count |
|---|---|
| CRITICAL | 0 |
| HIGH | 0 |
| MEDIUM | 7 |
| LOW | 9 |

**Overall risk assessment: LOW–MODERATE.** The codebase is unusually well-built: SQL is uniformly parameterized, webhook auth is HMAC over the raw body with constant-time comparison, `safeFetch` is a genuinely strong SSRF guard, CI workflows are least-privilege with SHA-pinned actions and `persist-credentials: false`, `npm audit` is clean across 408 dependencies, and no secrets are committed. The full local gate set (typecheck, lint, format, 404 tests, context pack, security floor at exactly 225/29, template manifest, build + dist-schema check) runs green.

The findings concentrate in one theme: **several invariants that `docs/SECURITY.md` presents as base-owned live code are, in this package, either module-supplied (unimplemented in base) or implemented but unpinned by any test here.** The extraction brought the code but not all of its tests — the exact issue-#9 pattern the repo's own CLAUDE.md warns about.

**Top 3 priorities:**

1. **Pin the untested invariants** (S1): tool lockdown, the frozen router spine order, the prompt slot order, and the skills-allowlist rejection currently have zero test coverage in this repo — a change to any of them goes green.
2. **Close the provenance override** (S3): a module manifest can silently flip base's `'auto'` (quarantined web-research content) registration to `'trusted'` with a bare `Map.set`.
3. **Guard the publish tag path** (S4): any commit carrying a `v*.*.*` tag publishes immutably to npm with a genuine provenance attestation; nothing verifies the commit is on `main`.

## Findings — MEDIUM

### S1. Four SECURITY.md §2 invariants have zero test coverage in this repository

**File:** `src/agent/core.ts` (lines 291–462), `src/routerIntercepts.ts` (82–96), `src/agent/promptSpine.ts` (164–169, 276–293), `src/agent/systemPrompt.ts` (106–116), `src/agent/skillsManifest.ts` (28–50)
**Severity:** MEDIUM
**Category:** Assurance / invariant enforcement

`docs/SECURITY.md` §4 admits two enforcement points arrived without tests and says both were closed (issue #9). The list is incomplete: at least nine test files referenced by base source comments and docs do not exist here (`routerInterceptChain.test.ts`, `systemPrompt.test.ts`, `systemPromptByteStability.test.ts`, `agentSkillsEnabled.test.ts`, `toolRegistry.test.ts`, `jobsRegistry.test.ts`, …). The only spine-adjacent test asserts an intercept cannot reuse `PRE_TURN_SPINE[0]`'s name.

**Impact:** Nothing in this repo would fail if `'WebFetch'` were dropped from `disallowedTools`, the `PRE_TURN_SPINE` order were changed (e.g. `confirm-intercept` moved after `addressed-gate`), a `SECURITY_SPINE` prompt clause were edited or moved below `persona-voice`, or `registerSkillsManifest`'s never-`'all'` rejection were relaxed. The security floor is structurally blind to an enforcement point with no test file at all.

**Fix:** Add package-boundary tests with matching `tests/security-floor.json` entries: assert `buildQueryOptions` output per tier (WebFetch/Task always disallowed, `tools: []` for member/guest), `assert.deepEqual` + `Object.isFrozen` on `PRE_TURN_SPINE`, verbatim presence and relative order of every `SECURITY_SPINE` clause in `buildGuidelinesBlock` output, and that `registerSkillsManifest({ enabledSkills: 'all' })` throws.

### S2. The `ToolContext` security helpers are declared by base but implemented by no one

**File:** `src/agent/tools/types.ts` (lines 25–28, 42–62), `src/index.ts:53`; contrast `docs/SECURITY.md` §2 invariants 3, 5, 9
**Severity:** MEDIUM
**Category:** AuthZ / contract honesty

`src/agent/tools/` contains only `types.ts`. The interface carries the four security-critical helpers (`requireConfirm`, `audited`, `callerScope`, `resolveMemberTarget`) and its comment claims they are implemented "here in exactly one place" — but every `see context.ts` reference points at a file in the **consumer's** repo, and `createAgent` never inspects what a module's `makeContext` returns. `docs/MODULE-API.md` is honest about this split; `docs/SECURITY.md` §2.3/§2.5/§2.9 state these as base-owned live code. Base ships `recordAdminAction` and `alertSuperAdmins` as two independent primitives — nothing pairs them, despite §2.9's "paired in one place so a domain file cannot implement half of it".

**Impact:** A second consumer inherits the appearance of four enforced controls and none of the enforcement. A module can ship an `audited` that skips the super-admin echo, or a `callerScope` returning `null` (unrestricted) for everyone, and boot cleanly with no gate noticing.

**Fix:** Ship the implementations — a base `makeBaseToolContext(caller, adapter, …)` that modules spread into their context. Until then, mark invariants 3 (sanitize half), 5, and 9 as `partial` in `docs/SECURITY.md` and correct the `types.ts` comment.

### S3. `registerProvenance` lets a module silently downgrade a base fail-closed registration

**File:** `src/storage/provenance.ts` (lines 29–33 vs 43–52)
**Severity:** MEDIUM
**Category:** AuthZ / privilege escalation via registration

Every other spine registry throws on re-registration; `registerProvenance` is a bare `Map.set` with no duplicate check, and `createAgent.ts:413` replays module `provenance` entries through it.

**Evidence:**
```ts
export function registerProvenance(reg: { id: string; trust: ProvenanceTrust }): void {
  registry.set(reg.id, reg.trust);   // no duplicate check
}
...
registerProvenance({ id: 'auto', trust: 'quarantined' });  // base
```

**Impact:** A module manifest containing `provenance: [{ id: 'auto', trust: 'trusted' }]` flips machine-ingested, injection-bearing web content from quarantined to trusted rendering at every retrieval site consulting `trustOf`, with no error and no log — defeating invariant 6.

**Fix:** Throw on re-registration of an existing id (seed the base four directly into the map, or arm the guard after them). Add a `SECURITY:` case asserting the throw; raise the floor entry.

### S4. `publish.yml` will publish any commit that carries a `v*.*.*` tag

**File:** `.github/workflows/publish.yml` (lines 86–90, 299–315)
**Severity:** MEDIUM
**Category:** Supply chain

The preflight checks only tag **format** and tag↔`package.json` **version agreement**. Nothing verifies the tagged commit is reachable from `main`. Branch protection does not cover tag refs without a separate tag ruleset, so anyone with `contents: write` (or a compromised contributor credential) can push `v0.6.5` at an arbitrary tree and publish it immutably — with a genuine provenance attestation naming this repository. CLAUDE.md's claim that the guard "keeps an unadjudicated commit off an immutable registry" overstates what the guard checks.

**Fix:** (1) In the preflight, after a `fetch-depth: 0` checkout: `git merge-base --is-ancestor "$GITHUB_SHA" origin/main || fail`. (2) Add a repository tag ruleset for `v*` restricting tag creation, and/or a `release` environment with required reviewers on the publish job. Control 2 is the enforceable one.

### S5. Discord slash-command dispatch bypasses the entire pre-turn spine

**File:** `src/platforms/discord/adapter.ts` (225–231), `src/platforms/discord/slashDispatch.ts` (66–73), `src/commands/registry.ts` (70–72)
**Severity:** MEDIUM
**Category:** AuthN/AuthZ

The WhatsApp `!` text-command path is a post-spine intercept inheriting block-list → role resolution → pause → rate-limit → budget, and receives the resolved role. `handleInteraction` dispatches straight from the raw Discord event: `SlashCommandDeps` carries only `filtered`, so base hands the handler no tier, and no block-list/pause/rate-limit check runs.

**Impact:** A user blocked via `block_user`, a paused agent, or a user over rate limit/budget can still drive every registered slash command. Mitigated by `slashCommandsEnabled` defaulting off and the commands being intended read-only — but the gate is entirely the module's to remember, which is the shape base is supposed to own.

**Fix:** In `handleInteraction`, check the block list (silent return, matching the zero-footprint property), check pause, resolve the role, and pass `caller: { userId, role }` in `SlashCommandDeps`. Pin with a `SECURITY:` test that a blocked user's interaction never reaches `command.discord.handle`.

## Findings — LOW

### S6. `FLEET_SUPERVISOR_TOKEN` is a base credential absent from `runtimeSecrets()`

**File:** `src/agent/secrets.ts` (36–52); `src/fleet/heartbeat.ts` (74, 165–170)
**Severity:** LOW · **Category:** Secrets

SECURITY.md §1: "every new BASE credential must be added to `runtimeSecrets()` by hand in the same diff that introduces it." The fleet heartbeat reads and transmits a bearer token; `runtimeSecrets()` does not include it, and it is read straight from `process.env` rather than a config slice. No egress path surfaces it today — defence-in-depth only.

**Fix:** Add it to `runtimeSecrets()` (ideally via a `fleet` config slice); add a `SECURITY:` case in `secrets.test.ts` and raise the floor entry.

### S7. Conversation-scoping parameters are optional, so omission fails open

**File:** `src/storage/repository/sessions.ts` (129–155); `src/storage/repository/interactions.ts` (128–169)
**Severity:** LOW · **Category:** AuthZ / data boundary

The SQL is correctly parameterized, but `userMessages(platform, userId)` with no `conversationIds` and `searchMemory(text, {})` are valid calls returning **unscoped** cross-conversation results. Base's own callers always pass the scope; a module tool that forgets the argument silently reads every conversation.

**Fix:** Make the scope a required explicit union on admin-facing readers — `scope: readonly string[] | 'unrestricted'` — so "no scope" must be written down.

### S8. `safeFetch`'s IPv6 denylist misses hex-group v4-mapped, `::ffff:0:0/96`, and 6to4 forms

**File:** `src/util/safeFetch.ts` (98–117)
**Severity:** LOW · **Category:** SSRF (defence in depth)

Verified by executing the real function: `::ffff:127.0.0.1` → blocked, but `::ffff:7f00:1` (same address, hex form), `0:0:0:0:0:ffff:7f00:1`, `::ffff:0:127.0.0.1` (RFC 6145), and `2002:7f00:0001::` (6to4 of 127.0.0.1) all pass. Node's `dns.lookup` normalizes the primary case to dotted form, so exploitation requires an attacker-controlled DNS record inside an already-allowlisted host plus a translation/relay path — narrow.

**Fix:** Expand to eight hex groups and check the well-known prefixes numerically instead of pattern-matching text; add the five forms to `safeFetch.test.ts` and raise the floor.

### S9. The migration runner takes no advisory lock

**File:** `src/storage/migrate.ts` (27–42)
**Severity:** LOW · **Category:** Concurrency

The single multi-statement query is correctly atomic and `EMBEDDING_DIM` cannot inject (zod-coerced positive int), but `createAgent.start()` migrates by default, so two replicas starting concurrently can race the catalog (`pg_type_typname_nsp_index` duplicate-key aborts despite `IF NOT EXISTS`). Availability-only; fails safe.

**Fix:** Prepend `SELECT pg_advisory_xact_lock(hashtext('agent-base-migrate'));` to the concatenated SQL.

### S10. Raw platform identifiers reach the logs at info level

**File:** `src/agent/core.ts` (578–582); `src/platforms/whatsapp/baileysAdapter.ts` (826, 972, 976, 1185)
**Severity:** LOW · **Category:** PII in logs

`hashId` exists exactly for this ("a WhatsApp conversation id IS the member's phone-number JID") but is applied at only five rate-limit telemetry sites. `core.ts:578` logs `conversationId` raw at info level; several WhatsApp warn paths log raw `jid`/`userId`. pino's redact paths cover token-shaped keys only.

**Fix:** `hashId()` the identifiers at those sites, or demote raw values to `debug`.

### S11. No TLS enforcement on the Postgres pool

**File:** `src/storage/db.ts` (11–21); `template/.env.example:13`
**Severity:** LOW · **Category:** Insecure default

No `ssl` option on the pool; `pg` defaults to plaintext when `sslmode` is absent from `DATABASE_URL`. The template ships a localhost example a scaffolded agent will edit for a remote database, and nothing warns. SECURITY.md names the interaction database (member PII) as protected asset #3.

**Fix:** At minimum, a loud `# Use sslmode=require for any non-localhost database` in `template/.env.example`; the enforcement version is a `dbSlice` refinement failing boot when the host is non-loopback and `sslmode` is absent/`disable`.

### G3. Fleet heartbeat spend window can double-count and is cross-clock

**File:** `src/fleet/heartbeat.ts` (109–121, 208–229)
**Severity:** LOW · **Category:** Concurrency / data correctness

`beat()` captures `now` from the app clock, then queries `created_at > watermark` with **no upper bound**; the watermark advances to `now`. A row inserted between the `now` capture and the query's execution is reported this beat and again next beat — contradicting the comment "consecutive reports cannot double-count the same row". Cross-clock (app watermark vs DB `created_at`) skew widens the window. Bounded impact: over-reporting fails safe against bosun's budget caps.

**Fix:** Bound the query (`created_at > $1 AND created_at <= $2`), with both edges from a consistent clock (`SELECT now()` or app clock for both).

### G4. `planComposition`'s "process untouched" guarantee has two persona-shaped gaps

**File:** `src/createAgent.ts` (345–375, 409–418); `src/agent/personaRegistry.ts` (34–47)
**Severity:** LOW · **Category:** Error handling / contract

Two modules each flagging a default persona, or registering personas with the same id, pass the "pure" plan pass and only throw inside `registerPersona` mid-step-4 — after the singleton registries are filled. That leaves the half-registered process the plan pass exists to prevent.

**Fix:** In `planComposition`, count cross-module `isDefault` claims (≤1) and detect duplicate persona ids.

### G5. Template upgrade: unresolved conflicts go invisible after one run

**File:** `scripts/upgrade-template.mjs` (111–128)
**Severity:** LOW · **Category:** Tooling

`applyUpgrade` writes inline conflict markers, then unconditionally resets the manifest baseline to the new template. On the next run the marker-laden file classifies as `localOnly` ("kept") — the tool reports clean while `<<<<<<<` markers remain. Also latent: inline mode reads UTF-8 (would corrupt a binary template file — none exist today), and a consumer's deliberate deletion of a template file is silently re-added.

**Fix:** Refuse to plan (or warn) when files contain conflict markers; consider keeping conflicted files out of the baseline reset.

## Checked and clean (no finding)

- **SQL injection:** every dynamic fragment across `src/storage/repository/**` builds `$n` placeholders; no user value is ever interpolated.
- **Webhook auth:** HMAC over the raw body, hex-validated, length-checked, `timingSafeEqual`; `timingSafeEqualString` hashes both sides so length never throws or leaks.
- **Command injection:** `execFile`/`spawnSync` with array argv throughout; the one `shell: true` is Windows-only with program-controlled arguments.
- **Prompt-injection quarantine:** `sanitizeName`/`untrustedEntryContent`/`sanitizeTextAttachment` strip `<>`/`[]`/C0-C1/U+0085 correctly; slot order frozen with the security spine above `persona-voice`.
- **Workflow injection:** no `pull_request_target`; untrusted inputs via `env:`; all actions SHA-pinned; `persist-credentials: false` everywhere; fork PRs get `contents: read`.
- **CONFIRM flow:** single-use (delete-before-expiry-check), tier re-resolved at confirm time, router emits the authoritative pending description itself.
- **Outbound filter:** all three adapters route every send through one `filtered()`; a throwing secret getter fails the send (fail closed).
- **Purge:** single transaction, sessions cleared before interactions, digest invalidation inside the transaction, `blocked_users` deliberately excluded from `forget_me`.
- **Dependencies:** `npm audit` → 0 vulnerabilities across 408 deps; deliberate `overrides` for known-problem transitives; Baileys correctly an optional peer.
- **Secrets:** none committed; both `.gitignore`s cover `.env`, keys, and WhatsApp auth state.
